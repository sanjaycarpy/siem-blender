# Python Event Processing

## Role of Python

Python acts as the communication layer between **Wazuh** and **Blender**.

Its main purpose is to receive security alerts generated by Wazuh, extract the relevant information, and prepare the events for 3D visualization.

```text
Wazuh
  │
  │ JSON alert
  ▼
Python
  │
  │ Processed event
  ▼
Blender
```

## Event Reception

The Python application runs on **macOS** and receives events generated by the Wazuh Manager running on the Raspberry Pi 5.

The first objective is to successfully receive a real Wazuh alert and display it in the terminal.

## JSON Parsing

Wazuh alerts are provided in JSON format.

Python extracts the information required by the visualization layer, such as:

- `timestamp`
    
- `rule.id`
    
- `rule.level`
    
- `rule.description`
    
- `agent.name`
    

The extracted data is converted into a simplified event structure that can be used by Blender.

## Event Processing

The Python layer acts as an intermediate processing layer.

```text
Wazuh JSON Alert
       │
       ▼
Parse JSON
       │
       ▼
Extract relevant fields
       │
       ▼
Create visualization event
```

This separation keeps the Wazuh data format independent from the Blender visualization logic.

## Communication with Blender

Once event reception and processing are working, Python will transmit the processed events to Blender.

The goal is to allow Blender to react dynamically to incoming security alerts.

For example, the alert severity could determine the type or intensity of a visual effect.

## Error Handling

The Python application should handle common communication problems, including:

- Invalid JSON data
    
- Lost network connection
    
- No incoming events
    
- Unexpected alert fields
    
- Blender unavailable
    

The objective is to prevent a single malformed event or connection failure from stopping the entire application.
